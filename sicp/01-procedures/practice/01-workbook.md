# 01 학습 워크북 — 평가, 치환 모델, 계산 과정

이 문서는 **[개념 교재](../lessons/01-evaluation-and-processes.md)를 읽은 직후** 진행하는 연습입니다. SICP 원서는 필요하지 않습니다.

## 먼저 알아둘 것

- **연습(Exercise):** 배운 개념을 스스로 설명하거나 짧은 코드를 작성하는 문제
- **실습(Lab):** 실행하기 전 예측하고, 코드를 실행하여 관찰한 뒤, 가설을 비교하는 실험
- **도전(Challenge):** 다른 문제에 배운 원리를 적용하는 독립 응용
- 이 워크북 → [실습 01](../labs/01-process-shapes.md) → [회고](../../../templates/reflection.md)의 순서로 진행하세요.
- 정답은 제공하지 않습니다. 문제를 풀다가 막힐 때는 개념 교재를 다시 읽거나 직접 작은 입력값으로 계산해 보세요.

## 연습 1 — 계산 순서 손으로 추적 (기본)

다음 코드에서 결과를 실행 전에 예상하고, 계산이 바뀌는 중간 단계를 세 줄 이상 써 보세요.

```scheme
(define (square x) (* x x))
(define (double x) (+ x x))
(+ (square (double 2)) (double 3))
```

**제출물:** 최종 값, 중간 계산식, '먼저 계산해야 하는 부분'에 대한 한 문장 설명.

## 연습 2 — 조건문은 무엇을 계산할까? (기본)

아래 코드가 오류 없이 결과를 낼지 예상하세요. 그렇다고 생각한다면 왜 0으로 나누는 부분이 실행되지 않는지 설명해 보세요.

```scheme
(if (< 2 5)
    (* 3 7)
    (/ 1 0))
```

그다음 조건을 `(> 2 5)`로 바꾼다면 어떻게 될지 예상하세요. **오류가 발생할 코드는 실행하지 않아도 됩니다.**

**제출물:** 두 경우의 예상 결과와 그 이유.

## 연습 3 — 평가 순서 비교 (중급)

```scheme
(define (square x) (* x x))
(square (+ 1 2))
```

1. 인수 `(+ 1 2)`를 먼저 계산한 후 함수를 적용하는 과정을 그리세요.
2. 인수 표현식을 먼저 함수 본문에 넣고, 그 후에 계산하는 과정을 그리세요.
3. 두 과정의 최종 값과 중간 표현식의 차이를 비교하세요.

**참고:** 일반적인 Scheme 호출과 다른 평가 모델을 비교하는 사고 실험입니다.

## 연습 4 — 미뤄진 연산 찾아보기 (중급)

```scheme
(define (sum-to n)
  (if (= n 0)
      0
      (+ n (sum-to (- n 1)))))
```

`(sum-to 4)`의 계산을 손으로 전개하고, 각 단계에서 아직 더해야 할 숫자가 무엇인지 표시하세요.

**제출물:** 단계별 표현식과 미뤄진 덧셈에 대한 설명.

## 연습 5 — 과정의 모양을 바꾸기 (심화)

연습 4의 `sum-to`를 현재까지의 합계와 카운터를 저장하는 방식으로 다시 작성하세요. 반복적으로 계산할 때 매 단계에 필요한 상태가 무엇인지 표로 정리하세요.

**제출물:** 직접 작성한 코드, 상태표, 두 방식의 차이.

## 독립 도전 — 계산 대신 설계하기 (심화)

숫자 `x`를 `n`번 곱하여 `x^n`을 계산한다고 합시다(`n`은 0 이상의 정수).

- 아직 처리할 곱셈이 쌓이는 프로시저를 만들어 보세요.
- 현재까지 계산한 결과와 카운터만 유지하는 프로시저를 만들어 보세요.
- `x=2, n=4`의 과정을 직접 추적해 보세요.
- 두 방식의 결과가 같은 이유를 설명해 보세요.

## 확인 질문

- 프로시저가 자기 자신을 호출한다는 사실만으로 공간 사용량을 판단해도 될까요?
- 치환 모델이 실제 컴퓨터 내부에서 문자열을 복사한다는 뜻일까요?
- 두 프로그램이 같은 답을 내더라도 왜 계산 과정은 다를 수 있을까요?
