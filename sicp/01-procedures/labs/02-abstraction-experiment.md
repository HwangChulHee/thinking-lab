# 실습 02 — 코드를 줄이는 것과 생각을 일반화하는 것은 같을까?

**학습 경로:** [교재 02](../lessons/02-higher-order-procedures.md) → [워크북 02](../practice/02-workbook.md) → 이 실습

## 1. 먼저 예상하기

합계 함수와 곱 함수가 있다고 가정하세요. 어떤 부분을 매개변수로 바꾸면 두 함수를 하나의 함수로 표현할 수 있을까요? 코드를 작성하기 전에 목록을 적으세요.

## 2. 실행 가능한 예제 확인

[예제 코드](../examples/higher-order.rkt)를 열어 보고 다음 명령어를 실행하세요.

```bash
racket sicp/01-procedures/examples/higher-order.rkt
```

`sum`, `product`, `accumulate`가 어떤 결과를 내는지 비교해 보세요.

## 3. 조건 변경 실험

`next` 함수가 1이 아니라 2씩 증가하도록 바꾸면 어떤 일이 일어날까요? `term`을 `square`로 바꾸면 어떤 일이 일어날까요? 실행 전에 결과를 예상하세요.

## 4. 추상화의 한계 찾기

`accumulate`의 `combine`에 뺄셈을 전달하면 어떻게 될지 예상하고 실행해 보세요. 결과가 직관과 다를 수 있는 이유를 **결합 순서**에서 찾으세요.

추가 탐구: 반복적 구현으로 바꾸면 결과가 같을까요? 코드가 틀린 걸까요, 아니면 추상화가 전제하던 성질을 확인해야 하는 걸까요?

## 5. 회고와 복습

- 함수 자체를 매개변수로 다룰 때 어떤 종류의 중복을 없앨 수 있었나요?
- 무엇이 공통되는 계산 구조인지 알아차리기 위해 어떤 질문을 해야 하나요?
- 3~7일 뒤 새로운 반복 계산 문제에서 함수의 공통 구조를 추출해 보세요.

**완료 조건:** 단순 출력 확인이 아니라 예상, 관찰, 원인 설명, 새 문제 적용을 남깁니다.
