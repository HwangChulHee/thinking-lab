# Lab 01 — Recursive procedure, iterative process

**SICP 2nd ed. §1.2.1** | Suggested prerequisite: §1.1.5–1.1.7

## Central question

> Does calling yourself recursively always mean the computation needs an ever-growing stack?

### 1 — Predict (before running anything)

Consider factorial written in two ways: one defers multiplications until a base case, the other carries a changing product and counter.

Write down:
- Every intermediate expression for input `4` using the substitution model.
- Which operations remain *deferred* at each step.
- What the smallest state needed to continue the computation contains.

**Do not run code yet.** Keep your original prediction, even if wrong.

### 2 — Observe

Run `../examples/processes.rkt`. Compare the trace output for both strategies.

Questions:
1. Do both give the same mathematical result?
2. Which process accumulates pending work?
3. What is the difference between a procedure that calls itself and a process whose space use grows recursively?

### 3 — Implement

Open `../exercises/ex01-factorial.rkt` and fill in the `TODO` expressions. The scaffold is intentionally incomplete; tests are included but no solution is provided.

Then try `n = 1, 4, 7`. Explain each base case.

### 4 — Original SICP practice

Work through **Exercises 1.9 and 1.10** in your own notes using the source text. For 1.9, draw the processes generated by the two addition procedures. For 1.10, focus on the growth pattern and resist guessing from one example.

Exercise references only: consult the original book for full wording.

### 5 — Transfer challenge

Without copying the factorial implementation, write **two procedures to compute the sum of integers from 1 to n**:
- One generates a linearly recursive process with pending additions.
- One generates a linearly iterative process with a small fixed-size state.

Predict both traces for `n = 4` before running them.

### 6 — Boundary investigation

Try to explain why the language runtime matters. In particular:
- What does a *proper tail call* guarantee in a Scheme-family language?
- Why should you not assume that the second strategy avoids stack growth if directly translated into Python?

You do **not** need to run out of memory to answer these questions.

### 7 — Reflection and delayed retrieval

Copy `../../../templates/reflection.md` into your own notes. In 3–7 days, implement iterative exponentiation without reviewing this lab and explain the state invariants.
