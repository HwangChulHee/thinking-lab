# 실습 01 — 재귀 프로시저와 반복적 계산 과정

**이 실습은 [개념 교재](../lessons/01-evaluation-and-processes.md) → [연습 워크북](../practice/01-workbook.md)을 끝낸 뒤 시작하세요.** 외부 책은 필요하지 않습니다.

## 실습과 연습은 무엇이 다를까?

워크북에서는 **스스로 생각해서 답을 만드는 훈련**을 했습니다. 이 실습에서는 **실행 전에 예측하고, 실제 출력을 관찰하고, 예상과 다른 이유를 분석**합니다.

### 1. 실행 전 예상하기

다음 질문에 먼저 답을 적어 두세요.

- 재귀 버전의 팩토리얼은 어떤 계산을 나중으로 미룰까요?
- 반복적 과정의 팩토리얼은 매 단계 어떤 정보만 기억하면 될까요?
- 둘 다 `4!`를 계산하면 결과가 같을까요?

## 2. 예제 실행하고 관찰하기

저장소 루트에서 아래 명령어를 실행하세요. [코드 보기](../examples/processes.rkt)

```bash
racket sicp/01-procedures/examples/processes.rkt
```

출력을 보고 예상과 비교하세요. 특히 재귀 버전은 함수에 **들어갈 때**와 **돌아올 때** 각각 로그가 나오지만, 반복적 과정은 상태를 갱신하며 다음 단계로 진행합니다.

- 로그의 순서가 왜 다른가요?
- 각각 어떤 정보를 보관해야 계산을 이어갈 수 있나요?
- 로그는 계산의 구조를 보여 줄 뿐, 실제 스택 메모리 사용량을 직접 측정한 결과는 아니라는 점에 유의하세요.

## 3. 직접 코드 완성하기

[연습 코드](../exercises/ex01-factorial.rkt)의 `TODO`를 채우세요. 정답 코드는 제공하지 않습니다.

- `factorial-rec`: 더 작은 문제를 먼저 해결하고 그 답에 `n`을 곱합니다.
- `factorial-iter`: `product`와 `counter`를 갱신하여 계산합니다.
- `n=0`과 `n=1`에서 어떻게 종료되는지 확인하세요.

완성 후 실행:

```bash
raco test sicp/01-procedures/exercises/ex01-factorial.rkt
```

테스트가 통과해도 실행 과정을 설명하지 못하면 끝난 것이 아닙니다.

## 4. 조건을 바꿔 보는 실험

`n=4` 대신 1 또는 6을 넣어 보세요. 원래의 예상과 실제 로그를 비교해 보세요. 종료 조건이 달라지면 어떤 차이가 있을지도 가설을 세워 보세요. 단, 무한 재귀를 유도하는 입력은 실제로 실행하지 않아도 됩니다.

## 5. 다른 문제로 적용하기

워크북의 정수 합 또는 거듭제곱 문제를 다시 보지 않고, **새로운 함수 이름과 상태 변수**로 직접 구현해 보세요. 자신이 사용한 상태가 계산을 계속하기에 충분한 이유를 설명하세요.

## 6. 기록하고 복습하기

[회고 템플릿](../../../templates/reflection.md)을 참고하세요.

- 예상과 실제 실행이 달랐던 부분은?
- '재귀 코드 = 스택 증가'라는 주장은 언제 부정확해질까요?
- 3~7일 뒤 같은 원리를 다른 계산 문제에서 재현할 수 있을까요?
